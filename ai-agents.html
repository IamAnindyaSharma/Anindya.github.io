AI agents: evaluation and job search

Two agents I built with Claude to take over repetitive, document-heavy work, while keeping a human in charge of every decision that matters.

PlatformClaudeFocusWorkflow automation, guardrailsSkillsAgent design, context design, scoping
Summary. I designed and built a bid-evaluation agent and a job-application agent. Each reads documents, applies defined rules, drafts structured output and stops for human approval before anything leaves the system.

01Why agents, not prompts

Both problems were the same shape: a repetitive, document-heavy workflow with clear rules, where a human makes the final call. A single chat prompt can answer a question; an agent can work through the whole workflow. I treated each agent like a product: a defined user, a job to be done, guardrails and a clear hand-off point.

02Agent 1: Bid evaluation

The job: read bid and tender documents, check each response against the evaluation criteria, and produce a structured assessment a reviewer can verify quickly.

STEP 1Ingest bid documents
STEP 2Map to evaluation criteria
STEP 3Flag gaps and deviations
STEP 4Draft reviewer summary

The agent does the reading and cross-checking; the reviewer keeps the judgement and the sign-off.

03Agent 2: Job search and applications

The job: turn a job posting into a tailored, truthful application without losing hours on each one.

STEP 1Read the posting
STEP 2Pick the best-fit CV
STEP 3Tailor it truthfully
STEP 4Draft application for approval

It works from screenshots, links, PDFs or pasted text, and never submits anything until I approve it.

04How I built them

Both agents run on Claude. The build was mostly product work rather than code:

CONTEXT

Gave each agent structured background: the criteria, my CVs and standing answers, and what good output looks like.

TASK

Wrote clear, step-by-step task instructions with explicit output formats.

ACCESS

Connected only what each workflow needs: a working folder and email.

GUARD

Built in approval gates, so nothing is sent or submitted without a human yes.

05Design choices

What I prioritised

  • Truthfulness: the job agent tailors emphasis, never invents experience
  • Human in the loop at every irreversible step
  • Least access: each agent only touches what its job needs
  • Verifiable output: summaries that point back to the source

What I deliberately avoided

  • Fully autonomous sending or submission
  • Broad inbox or file access "just in case"
  • Opaque scores without the reasoning behind them

06What I learned

  • Most of the quality comes from context and instructions, not the model
  • Approval gates make people trust and actually use an agent
  • Scoping an agent is a product decision: who it serves, and where it must stop

What this project shows

  • Turning a manual workflow into a scoped, reliable AI product
  • Designing guardrails and approval points, not just prompts
  • Shipping applied AI that I actually use
